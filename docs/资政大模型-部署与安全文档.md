## 一、部署方案（FR5.1）

### 1.1 本地部署（当前方式，已可用）

| 项 | 说明 |
| --- | --- |
| 嵌入模型 | `BAAI/bge-small-zh-v1.5`（512 维），本地 CPU 加载，首次调用时载入内存 |
| 知识库 | `data/knowledge_base/`（类别/文档/文本块向量 + 索引，可随时重建） |
| 检索 | 完全本地（三级层次检索，无外部调用） |
| 生成模型 | OpenAI 兼容接口（默认 DeepSeek，`.env` 配置 `LLM_API_KEY/LLM_BASE_URL/LLM_MODEL`） |
| 应用服务 | Flask，`python app/server.py`，监听 `127.0.0.1:8000` |
| 依赖 | `requirements.txt`；Python ≥3.9 |

启动步骤：

```bash
pip install -r requirements.txt          # 首次
copy .env.example .env                    # 填写 LLM_API_KEY / LLM_BASE_URL / LLM_MODEL
python app/server.py                      # 访问 http://127.0.0.1:8000
```

### 1.2 政务云 / 内网部署（推荐方案）

政务场景数据不出域，建议如下调整：

1. **生成模型本地化**：将 `LLM_BASE_URL` 指向内网部署的推理服务（如 vLLM 部署 Qwen/DeepSeek 开源权重），或替换为国产化一体机；嵌入模型已完全本地，无需调整。
2. **网络隔离**：应用只监听内网地址（`host=0.0.0.0` 配防火墙策略，或反向代理 + HTTPS）。
3. **数据落地**：语料、知识库、审计日志均保存在政务云存储 / 数据库，遵循等保要求。
4. **密钥管理**：`.env` 中的密钥由部署平台（如 KMS / 环境变量注入）管理，禁止入库、入镜像。

## 二、数据合规检查（FR5.2）

### 2.1 数据来源合规

- 语料全部来自**政府公开发布的政府工作报告**（国务院 / 广东省 / 深圳市及各区），抓取自政府官网"工作报告"栏目（`scripts/crawler/`，支持增量去重）。
- 均为公开政务信息，不涉及个人隐私、涉密内容；项目内仅做文本加工与检索，不对外发布原文。
- 残缺 / 异常文件已在清洗阶段标记（如坪山 2021 仅网页导航无正文），不进入知识库。

## 三、输出可控（敏感词过滤）

### 3.1 机制（已实现）

- 模块：`src/security/compliance.py`
- **输入侧**：`/api/ask` 对用户问题先做 `check_content()`，命中敏感词直接拒绝（HTTP 400），不进入检索与生成。
- **输出侧**：生成答案后再做 `check_content()`，命中即拦截（不返回给用户），并记录审计。
- 词表：
  - 内置红线词表（违法内容类：制毒 / 贩毒 / 走私枪支 / 传播淫秽 / 组织卖淫 / 赌博网站 / 诈骗教程 / 黑客攻击教程 等）。
  - 自定义词表：`data/config/sensitive_words.txt`（每行一词，支持 `#` 注释），用于按项目/属地口径补充政治表述等敏感词，重启即生效。

### 3.2 使用

```bash
python -m src.security.compliance --check "测试文本"   # 合规通过返回 0，命中返回 1
```

### 3.3 提示词约束

生成提示词（`src/generate/answer.py` 的 `ANSWER_PROMPT`）要求：仅基于参考资料、专业规范政务语言、资料不足时明确说明——从源头约束输出范围与口径。

## 四、可审计性

- 运行时按需创建 `data/logs/audit.jsonl`（追加式 JSONL），记录 `ask`、`blocked` 和 `error` 事件。
- 默认只记录问题哈希与长度，不记录用户问题或增强查询原文；仅在显式设置 `AUDIT_LOG_RAW_TEXT=1` 时记录原文。
- 运行日志已被 `.gitignore` 忽略，可接入部署环境的统一审计平台，不进入源码仓库。

## 六、已知限制与改进建议

1. **敏感词表需持续维护**：内置词表为通用红线，政治口径类词建议按主管部门要求补充到 `sensitive_words.txt`。
2. **审计合规**：政务云部署时建议将审计日志接入统一日志平台（Syslog / 等保审计系统），保留期按监管要求配置。
3. **LLM 外呼风险**：当前生成环节外呼云端 API，数据不出域场景需按 1.2 替换为内网模型。
4. **并发与限流**：Flask 开发服务器面向单用户验证；正式环境建议接入 WSGI（如 gunicorn/waitress）+ 限流与 WAF。
