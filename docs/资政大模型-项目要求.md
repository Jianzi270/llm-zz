# 资政大模型 — 项目要求（Requirements）

> 依据《立项报告》结题目标和当前自研实现编制。
> 更新日期：2026-09-09

## 1. 项目概述

**项目名称**：资政大模型（基于垂直领域大模型的政府智库报告生成智能体）

**结题目标**：搭建可持续更新的政务知识库，接入大语言模型，实现专业化、结构化、可溯源的政务问答和材料生成。

**正式技术路线**：自研 DC-RAG。知识库按“类别 → 文档 → 文本块”组织，检索结果作为可信上下文提交给 OpenAI 兼容的大模型接口。项目不依赖第三方工作流平台。

## 3. 功能需求（FR）

### FR1 数据采集与更新

- FR1.1 可从政府官方网站抓取公开政务材料，支持按来源选择和预览。
- FR1.2 提供一键更新入口，将新数据送入清洗、摘要、切分、聚类、知识库重建和检索验证流程。
- FR1.3 抓取失败、正文异常或验证失败时以非零退出码结束，禁止静默成功。

### FR2 知识库构建

- FR2.1 清洗、切分、摘要、向量化和聚类流程可复现。
- FR2.2 基于 GMM 软聚类构建“类别 → 文档 → 文本块”树形索引。
- FR2.3 元数据至少包含标题、层级、地区和年份，并贯穿切分、索引和检索结果。
- FR2.4 支持按内容指纹复用未变化文本块的向量。
- FR2.5 可导出文档级和文本块级标准 JSONL 备份。

### FR3 检索与生成

- FR3.1 支持用户输入增强；增强失败时回退原问题。
- FR3.2 按类别、文档、文本块进行层次检索，同时保留扁平检索基线用于对比。
- FR3.3 支持年份、地区等元数据约束，并保证结果具有文档多样性。
- FR3.4 生成内容必须基于参考资料，返回来源元数据，资料不足时明确说明。
- FR3.5 支持政策问答、材料摘要、报告草稿和情报简报四种模式。

### FR4 Agent 与应用

- FR4.1 提供面向用户的 Web 应用，串联输入校验、合规检测、检索、生成和来源展示。
- FR4.2 提供健康检查、请求大小限制、错误编号和生产级 WSGI 启动入口。
- FR4.3 应用与核心链路均由仓库代码实现，不依赖平台专属配置或标识符。

### FR5 安全与合规

- FR5.1 支持本地或政务云/内网部署。
- FR5.2 API 密钥只通过环境变量注入，不进入版本库。
- FR5.3 支持输入、输出双侧敏感词检查。
- FR5.4 运行日志默认只记录问题哈希、长度、来源和耗时，不记录用户原文；运行日志不纳入版本管理。

## 4. 非功能需求（NFR）

| 编号 | 需求 | 验收要求 |
| --- | --- | --- |
| NFR1 | 可维护性 | 代码、文档和必要数据纳入 Git；目录和运行命令清晰 |
| NFR2 | 可复现性 | 数据处理、知识库构建、测试和评估均可由脚本重跑 |
| NFR3 | 可更新性 | 新政策可通过一键流程入库，失败可被检测 |
| NFR4 | 检索质量 | DC-RAG 文档级指标不低于扁平基线，关键验收问题命中目标材料 |
| NFR5 | 生成质量 | 输出结构化、可溯源，并通过事实、文风和公文规范复评 |
| NFR6 | 安全性 | 原始异常不返回客户端；用户原文默认不落盘；正式环境具备认证、限流与 HTTPS |
| NFR7 | 性能与成本 | 未变化向量可复用；模型调用支持重试并记录耗时 |

## 5. 验收标准

- [x] 至少 160 篇有效语料进入层次化知识库，索引数量一致且可重建。
- [x] 一键更新链路可执行“爬取 → 清洗 → 摘要 → 切分 → 聚类 → 重建 → 验证”。
- [x] DC-RAG 按类别、文档、文本块检索，支持元数据约束和来源返回。
- [x] Web 应用端到端支持四类生成任务，并具备基础安全校验。
- [x] 核心单元测试、检索评估和端到端验收脚本可复现。
- [ ] 12 道生成答案完成人工事实、文风和公文规范复评。
- [ ] 检索评测集扩充到 50—100 题，补齐 nDCG 和生成忠实度指标。
- [ ] 正式部署接入认证、限流、HTTPS 和统一日志平台。

## 6. 约束与假设

1. 语料仅使用可公开访问的政府材料；新增来源须保留来源 URL 和抓取记录。
2. 嵌入模型默认使用本地 BGE；生成模型通过兼容接口配置，可替换为内网模型服务。
3. 自动更新脚本不自动执行 Git 提交或推送，新增材料需人工审核后入库。
4. 经费按立项预算执行：资料购置约 800 元、设备与计算资源约 1700 元、应急预留 500 元。
