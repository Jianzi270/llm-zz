# 资政大模型 — 结题报告

> **项目名称**：资政大模型——基于垂直领域大模型的政府智库报告生成智能体
> **项目单位**：哈尔滨工业大学（深圳）大一年度项目
> **报告日期**：2026-08-07

---

## 一、项目概述

### 1.1 项目背景

政府工作报告等政务语料具有**逻辑性强、层次分明、年份序列化**的特点。传统问答系统直接对全文做扁平检索，易被同源文档的高相似内容分散干扰。本项目构建**基于文档聚类的检索增强生成（DC-RAG）**智能体，实现政务文字与回答生成的专业化、结构化。

### 1.2 结题目标

> **搭建好知识库，部署大语言模型，实现政务文字及回答生成专业化、结构化。**

核心链路：`输入增强与向量化 → 文本检索查询 → 大模型生成输出`

### 1.3 技术路线（立项承诺）

- **DC-RAG**：知识库构建（文档向量化 → GMM 软聚类 → 类别-文档-文本块树形知识库）+ 答案生成（问题增强向量化 → 按类别/文档/文本块顺序检索 → 大模型生成）
- **智能体应用**：自研 Web 应用串联输入增强、DC-RAG 检索、生成与来源展示，检索环节全本地

## 二、系统总体设计

### 2.1 系统架构

```
┌────────────────────────── 应用层 ──────────────────────────┐
│  自研智能体 Web 应用（app/server.py + index.html）            │
│  输入合规检查 → 问答接口 → 输出合规检查 → 审计日志             │
├────────────────────────── 生成层 ──────────────────────────┤
│  C4 生成（LLM，OpenAI 兼容：DeepSeek；政务结构化提示词）      │
│  双路检索融合（增强查询 + 原查询，合并去重）                  │
├────────────────────────── 检索层（DC-RAG） ─────────────────┤
│  类别裁剪（类别向量） → 文档筛选（文档向量） → 文本块检索       │
├────────────────────────── 知识库层 ─────────────────────────┤
│  8 类 / 160 篇文档 / 15546 文本块（BGE-small-zh-v1.5，512维）│
├────────────────────────── 数据层 ──────────────────────────┤
│  161 篇清洗语料（160 篇有效入库）+ 元数据 + 摘要 + 文本块      │
│  爬虫（深圳政府网，增量去重，定时可配）                       │
└────────────────────────────────────────────────────────────┘
```

### 2.2 关键技术选型

| 环节 | 选型 | 说明 |
| --- | --- | --- |
| 嵌入模型 | `BAAI/bge-small-zh-v1.5` | 512 维，中文政务适配，本地 CPU 部署；查询侧加检索指令前缀 |
| 文档摘要 | 推理大模型生成式（LLM 摘要向量作为文档代表向量） | 提取式兜底；`max_tokens=1500` 避免推理 token 不足 |
| 聚类 | PCA 降维（512→75）+ BIC 选类 + GMM 软聚类 | 自动 k=3，细化 k=8 按区域划分，提升类别区分度 |
| 检索 | 三级层次检索（类别→文档→文本块） | 与扁平 top-k 基线对比验证 |
| 生成 | OpenAI 兼容接口（DeepSeek 推理模型） | 温度 0.3，结构化政务提示词，引用来源 |
| 应用 | Flask Web 服务 | 聊天界面，展示增强查询与来源文档 |

## 三、实施过程

### 阶段 0：资产保全（最高优先级）

> 项目因管理不善曾丢失主要代码。重建从版本管理和存量语料保全开始。

- **P1** git 仓库初始化 + 首次提交（151 个文件）
- **P2** 远程备份至 GitHub（`Jianzi270/zizhengLLM`）
- **P3** 目录规范 + README（`src/`、`data/`、`scripts/`、`docs/`、`app/`）

### 模块 A：数据层

- **A1 盘点与校验**：160 个 txt 全部 UTF-8 可解码，无空文件（`data/inventory/data_inventory.csv`）
- **A2 元数据标注**：级别（国家12/省12/市26/区110）+ 区域 + 年份（`data/metadata/metadata.csv`）
- **A3 清洗流水线**：去 BOM/TAB/全角空格、压缩空行、正文起点识别、残缺检测（`scripts/clean_text.py`，161 篇全量清洗）
- **A4 爬虫**：深圳政府网"工作报告"栏目，https 回退 http，增量去重（新增 14 篇，含 2026 年报告）

### 模块 B：知识库构建（DC-RAG 核心）

- **B1 嵌入模型**：BGE-small-zh-v1.5 本地部署，自测通过
- **B2 文档切分**：160 篇有效文档 → **15546 文本块**（标题独立成块、超长按句切分 ≤512、短段并入）
- **B3 摘要生成**：LLM 生成式 + 提取式双模式，161 篇基线摘要
- **B4 GMM 软聚类**：PCA + BIC + GMM，细化 **k=8** 按区域清晰划分
- **B5 层次化知识库**：类别→文档→文本块三级索引（8 类 / 160 篇 / 15546 块）
- **B6 数据集导出备份**：通用文档 JSONL + 文本块 JSONL（`data/export/`）

### 模块 C：DC-RAG 检索与生成

- **C1 输入增强**：LLM 改写查询（补全上下文/提取主题地域时间），失败回退原文
- **C2 DC-RAG 检索**：三级顺序检索 + 扁平基线对比
- **C3 质量评估**：12 题评测集，DC-RAG 块级命中率 58% vs 简化 RAG 17%
- **C4 生成**：增强→双路检索融合→上下文→LLM 生成结构化政务答案（12/12 生成成功）

### 模块 D：应用与安全合规

- **D1-D4 自研智能体应用**：复用 C1→C2→C4 完整链路（检索全本地，无平台专属依赖）
- **D5 安全与合规**：输入/输出双侧敏感词过滤 + 审计日志 + 部署与安全文档

### 模块 E：集成与验收

- **E1 系统集成与联调**：端到端联调脚本，快速 9/9、完整（含 LLM）11/11 通过

## 五、质量评估

### 5.1 检索质量（C3）

| 指标 | DC-RAG | 简化 RAG |
| --- | --- | --- |
| 文档级 Recall@3 | 12/12（100%） | 7/12（58%） |
| 文档级 MRR | 0.958 | 0.361 |
| **块级 Recall@3** | **12/12（100%）** | **2/12（17%）** |

> **结论**：在当前 12 题回归集中，DC-RAG 通过“类别→元数据约束→文档→文本块”提升了同区域跨年份检索准确率。由于样本较小，不作统计学显著性结论。
>
> 优化历程：文档向量改用 LLM 摘要向量（17%→58%）、查询加 BGE 检索前缀、聚类细化 k=8。

### 5.2 生成质量（C4）

旧版结果中有 6 题未包含目标文档。优化后已重新生成：12/12 成功，12/12 包含目标文档；完整 E2E 同时断言“深圳2025年GDP增长目标”命中 2025 年报告和 5.5%。人工文风、事实表述和公文规范复评仍需完成。

### 5.3 系统联调（E1）

端到端联调（数据层→知识库→检索→生成→应用）快速模式 9/9、完整模式（含 LLM）11/11 全部通过，全流程无断点，运行稳定。

### 5.4 端到端实测示例

> **提问**：深圳2025年GDP增长目标是多少？
> **C1 增强**：2025年深圳市地区生产总值（GDP）增长目标是多少？
> **C2 检索**：前三个文本块均命中深圳市政府工作报告（2025 年）
> **C4 生成**：根据《深圳市政府工作报告（2025年）》…深圳 2025 年 GDP 增长目标为 **5.5%**（引用来源）

| 要求 | 实现 |

## 七、创新点

1. **DC-RAG 层次化检索**：按“类别→元数据约束→文档→文本块”检索，当前回归集块级命中率为 100%，扁平基线为 17%。
2. **LLM 摘要作为文档代表向量**：相比文本块均值向量，文档级 Recall@3 从 17% 提升至 58%。
3. **双路检索融合**：增强查询 + 原查询合并去重，缓解年份偏移导致的漏检。
4. **自研智能体闭环**：复用完整 DC-RAG 链路构建 Web 应用，检索环节全本地，同时提供通用数据集备份。
